安装与更新文档

Mac 使用内置蓝牙。Linux 使用 Docker 宿主机上的蓝牙适配器，首次部署先检查 BlueZ 和系统 D-Bus。

Mac 安装 ZIP Mac Homebrew Linux Docker Compose 安装与检查 BlueZ 首次连接 常见错误

Mac 安装 ZIP

需要 Apple Silicon 和 macOS 14 或更新版本。

  1. 从下载区获取 Mac ZIP，解压后将 CUKTECH Studio 拖到「应用程序」。
  2. 打开 App，按系统提示允许蓝牙访问，再从菜单栏打开工作台。

测试版使用临时签名，首次打开时 macOS 可能会要求确认来源。

更新

退出正在运行的 App，再用新版 ZIP 中的 App 替换「应用程序」里的旧版。配置和历史记录保存在用户数据目录。

Mac 通过 Homebrew 安装

系统要求与 ZIP 安装相同。已经手动安装同名 App 时，先退出并把旧 App 移到备份位置。

brew install --cask morty626/tap/cuktech-studio-beta

Homebrew 7 如出现信任提示，按提示仅信任该 Cask。安装后从菜单栏打开工作台。

更新

brew update
brew upgrade --cask morty626/tap/cuktech-studio-beta

Linux Docker Compose

在实际运行 Docker Engine 的 Linux 主机上执行以下步骤。后端通过宿主机的系统 D-Bus 调用 BlueZ。Docker 若运行在虚拟机里，先把蓝牙适配器直通给这台虚拟机，再在虚拟机里检查。

1. 检查 Docker

docker info
docker compose version

第一条应能显示 Server 信息，第二条应显示 Compose 2.24.4 或更高版本。缺少 Docker 时，按发行版的Docker Engine 安装说明安装；已有 Engine 但没有 docker compose 时，安装Compose 插件。

2. 安装与检查 BlueZ

先运行 bluetoothctl --version。如果提示 command not found，在宿主机安装 BlueZ。以下命令适用于使用 systemd 的 Debian 和 Ubuntu。

sudo apt update
sudo apt install bluez
sudo systemctl enable --now bluetooth.service

在同一台主机上逐项检查。使用其他发行版时，先通过其包管理器安装 BlueZ 服务和提供 bluetoothctl 的工具包。

systemctl is-active bluetooth.service
test -S /var/run/dbus/system_bus_socket && echo "D-Bus socket OK"
bluetoothctl list
bluetoothctl show

应依次看到 active、D-Bus socket OK、至少一个 Controller，以及控制器信息中的 Powered: yes。某项未通过时，先看下面的常见错误。

3. 保存模板并启动

在新目录里，把下载区的 Linux Compose 模板保存为 compose.yaml。在该目录执行：

docker compose config --quiet
docker compose up -d --wait --wait-timeout 120
docker compose ps

配置检查成功时没有输出。启动后应能看到 backend 和 frontend 在运行，后端健康检查通过。在部署主机的浏览器打开 http://127.0.0.1:28753/。

4. 首次连接充电器

首次使用新的数据卷时，工作台会登记本套后端。给充电器通电，在「系统配置」中添加或导入设备，核对设备名称，再查看 BLE 连接和认证状态。如果同一台充电器正由另一套 Studio 控制，先断开那边的连接。

容器健康表示 HTTP 服务就绪。接入一个用电设备，确认对应端口的读数随负载变化，才算验证了蓝牙数据链路。

更新

在原目录执行以下命令，并继续使用原来的 Compose 项目名和数据卷。

docker compose pull
docker compose up -d --wait --wait-timeout 120

模板默认跟随 beta 渠道。需要固定测试版本时，可以在同目录的 .env 中设置 CUKTECH_VERSION 为对应的发布标签。

更新前备份设备配置和充电历史。需要停机备份时，先运行 docker compose stop，备份完整的 backend-data 和 frontend-data 命名卷，再启动。docker compose down -v 会删除这两个卷。

常见错误

Linux 的服务检查在 Docker 宿主机执行。涉及 docker compose 的命令，在保存 compose.yaml 的目录执行。

docker info 提示无法连接 Docker daemon

用 docker context show 核对当前连接的主机。在使用系统级 Docker Engine 的 Debian / Ubuntu 上，用 systemctl is-active docker 检查服务；若已安装但未启动，执行 sudo systemctl start docker。如果报错是访问 Docker socket 时 permission denied，用已有 Docker 管理权限的账号操作，再用 docker info 确认能看到 Server 信息。

找不到 bluetoothctl，或 bluetooth.service 未启动

出现 bluetoothctl: command not found 或 Unit bluetooth.service could not be found，按宿主机 BlueZ 安装步骤补齐软件包。若服务存在但处于 inactive，运行 sudo systemctl start bluetooth.service。启动失败或被跳过时，查看本次开机的服务日志，再检查适配器是否已被内核识别。

systemctl status bluetooth.service --no-pager
journalctl -b -u bluetooth.service -n 50 --no-pager

No default controller available，或 Powered: no

先运行 bluetoothctl list。列表为空时，检查宿主机上的 ls /sys/class/bluetooth 是否列出 hci0 等控制器。若没有，检查适配器连接、驱动和固件；虚拟机还要核对 USB 直通。内核日志可用 sudo journalctl -k -b | grep -i bluetooth 查看。

控制器存在但显示 Powered: no 时，用 rfkill list bluetooth 检查阻止状态。Debian / Ubuntu 缺少此工具时可用 sudo apt install rfkill 安装。若为 Soft blocked: yes，运行 sudo rfkill unblock bluetooth；若为硬件阻止，先检查设备开关或固件设置。随后执行 bluetoothctl power on，用 bluetoothctl show 确认 Powered: yes。

启动时报 system_bus_socket 挂载失败

模板直接挂载 /var/run/dbus/system_bus_socket。若报告 bind source path does not exist，回到 Docker 宿主机运行下面的命令。最后一条应输出 socket。

systemctl status dbus.socket --no-pager
LC_ALL=C stat -Lc '%F' /var/run/dbus/system_bus_socket

以 Debian / Ubuntu 为例，缺少系统 D-Bus 时安装 sudo apt install dbus；若 socket 单元已安装但未启动，运行 sudo systemctl start dbus.socket。这个路径由系统服务创建，手工建立同名文件或目录无法提供总线。确认路径是 socket、bluetoothctl show 能返回控制器后，再运行启动命令。

启动超时、后端 unhealthy 或端口已被占用

先看哪个服务退出，以及它退出前的报错。模板会等待后端健康检查成功后再启动前端。

docker compose ps -a
docker compose logs --tail=80 backend frontend
ss -ltnp | grep -E ':(28753|28759)\b'

若报告 address already in use 或 port is already allocated，在同目录的 .env 中只调整冲突的端口，例如 CUKTECH_FRONTEND_PORT=28754。后端对应 CUKTECH_BACKEND_PORT。重新执行 docker compose up -d --wait --wait-timeout 120，再用新端口访问。已有安装若修改后端端口，还要在工作台的后端地址设置里同步原有记录。

服务器本机能打开工作台，另一台电脑打不开

默认前端绑定在服务器的 127.0.0.1:28753。在自己的电脑访问这个地址，访问的是自己的电脑。若已有 SSH 登录权限，可从自己的电脑建立端口转发。把示例用户名和地址换成实际值：

ssh -N -L 28753:127.0.0.1:28753 user@192.168.1.20

保持该终端打开，再在自己电脑的浏览器访问 http://127.0.0.1:28753/。结束访问时按 Ctrl+C 关闭转发。

页面能打开，但充电器离线或没有读数

先确认宿主机的 bluetoothctl show 显示 Powered: yes，再检查充电器供电、与适配器的距离，以及其他控制端是否仍占用连接。若界面提示认证失败，在「系统配置」中核对导入的是当前充电器。重新连接后，按首次连接中的方法检查实际端口读数。

Mac 打开了 App，却找不到设备

从菜单栏打开工作台，触发一次蓝牙连接。确认 Mac 的蓝牙已打开，并在「系统设置 → 隐私与安全性 → 蓝牙」中允许 CUKTECH Studio 使用蓝牙。若此前拒绝过，修改权限后退出并重新打开 App，再查看连接状态。
